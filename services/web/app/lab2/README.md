## 원칙 — 골격은 VS Code, 마감은 우리 것

레이아웃(사용성)은 검증된 것을 그대로 쓰고, 마감(정체성)만 우리 것으로 간다. Cursor가 VS Code와 갈라진 방식이다.

**Cursor식 응용 4가지 = 차별화의 전부**
1. 상태바의 **파란 띠 제거**(VS Code의 가장 강한 시각적 서명)
2. 액센트를 파랑 → **시그널 앰버**, 그리고 "지금 어디인가"에만(장식 금지)
3. 크롬 감량
4. 영역 구분을 보더가 아니라 **명도 차**로(에디터 `#1f1f1f` > 크롬 `#181818`)

**모서리는 각진 채로 유지** — Cursor는 라운드를 더해 갈라졌지만 우리는 각짐이 기존 정체성(Instrument)이라 같은 논리의 반대 방향으로 간다.

## 파일 구조 — SEO가 이 경계에서 갈린다

```
layout.tsx          server  ← 메타데이터(title 템플릿)
  WorkspaceShell    client  ← 셸 전체(탭·사이드바·패널·상태바·상태 보유)
    page.tsx        server  ← 각 문서의 메타데이터
      *View.tsx     client  ← 인터랙션만
```

**client 컴포넌트의 `children`은 server 컴포넌트여도 된다.** 이걸 모르면 셸을 client로 만드는 순간 하위 전체가 client가 되고, `metadata`를 export할 수 없어 **페이지별 제목·설명이 사라진다**(문제 상세가 검색 자산의 거의 전부인데).

상태가 없는 화면(`status`·`verification`·`p/[id]/verification`)은 client를 아예 쓰지 않는다.

## 상태와 저장 ([workspace.tsx](workspace.tsx))

| 무엇 | 어디에 | 범위 |
|---|---|---|
| 코드 초안 | localStorage | 문제별 · **언어별** · 영구 |
| 취향·배치(폭·높이·분할) | localStorage, **비율로** | 영구 |
| 탭 목록 | sessionStorage | **세션 한정** |

**탭이 세션 한정인 이유**: "어제 풀다 만 문제로 복귀"의 본체는 탭이 아니라 **코드**다. 코드를 보존하면 탭은 영구일 필요가 없고, 탭 축적 문제도 같이 사라진다.

⚠️ **랩 한계**: 계정 동기화(다른 기기에서도 따라오기)는 api 설정 테이블이 필요해 **본 서비스 적용 시**에 붙인다. 여기서는 브라우저 저장소만 쓴다 — 설정 화면 하단에 그렇게 적어뒀다.
