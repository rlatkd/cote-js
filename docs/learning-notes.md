## 시스템 설계

### SSE vs WebSocket — 채점 알림엔 왜 SSE인가
채점 결과 알림은 **서버→클라이언트 단방향**이다. WebSocket은 양방향 채널이라 연결 관리(핸드셰이크 업그레이드·재연결·프록시 설정)가 더 무겁다. SSE(Server-Sent Events)는 일반 HTTP 위에서 동작하고 자동 재연결이 내장돼 있어 단방향 푸시엔 더 단순한 정답. 양방향(예: 실시간 협업)이 필요해지면 그때 업그레이드한다. **면접 포인트**: "기술 선택은 요구 방향성(단방향/양방향)부터 따진다." — 2026-07-25 12:48

### DB 단일 작성자 원칙 (single writer per schema)
폴리글랏에서 두 언어(Go·Prisma/TS)가 같은 테이블에 쓰면 스키마 마이그레이션의 주인이 없어진다 — 한쪽이 컬럼을 바꾸면 다른 쪽이 런타임에 깨짐. 그래서 **스키마당 작성자 하나**를 규칙으로 박고, 다른 서비스는 API/이벤트로만 접근한다(judge는 아예 DB 접근 금지, 결과는 Kafka 이벤트). 이는 MSA의 "database per service" 패턴의 완화형이다. — 2026-07-25 12:48

### QoS 레인 분리 — head-of-line blocking
같은 큐에 성격이 다른 작업(인터랙티브 예제 실행 / 정식 제출 / AI 검증 배치)을 섞으면, 대량 배치가 앞을 막아 유저 요청이 굶는다(head-of-line blocking). 해법은 **레인(토픽/우선순위) 분리** + 소비자(judge 워커)의 레인별 소비 정책. 실무의 "배치와 온라인 트래픽을 절대 같은 풀에 두지 말라"와 같은 원리. — 2026-07-25 12:48

### 서비스 경계는 "다르게 스케일하는 곳"에 긋는다
AI를 3서비스로 쪼갰다가 2로 병합한 근거. 생성(LLM 호출)과 검증(교차검증 오케스트레이션)은 둘 다 경량 I/O 작업이고 항상 한 흐름으로 돌아서 네트워크 경계의 실익이 없다. 반면 임베딩 서빙(scout)은 모델을 메모리에 상주시키는 다른 종의 워크로드다(RAM/GPU·기동시간·스케일 단위가 다름). **경계 기준 = 배포·스케일 특성의 차이**이지, "설명하기 좋은 분해"가 아니다. — 2026-07-25 12:48

### 샌드박스 격리 3요소 (judge 예정)
남의 코드 실행의 격리는 커널 기능 3종의 조합: **cgroups**(CPU·메모리·프로세스 수 상한 — fork bomb 방어), **namespaces**(pid/net/mount 시야 격리 — 네트워크 차단), **seccomp**(허용 시스템콜 화이트리스트). Docker는 이 셋의 포장지일 뿐 컨테이너 하나로는 보안 경계가 아니다. Go를 judge에 쓰는 이유 중 하나가 이 커널 기능들의 레퍼런스 구현(runc/gVisor)이 전부 Go라는 것. — 2026-07-25 12:48

## 백엔드 (hub / NestJS)

### 프론트·백 타입 공유의 실체 — contracts 패키지 (짝 A)
arena(Next)와 hub(NestJS)가 같은 TS라서 `@cotejs/contracts`에 도메인 타입+zod 스키마를 한 벌만 둔다. 컴파일 타임(TS 타입)과 런타임(zod 검증)을 **같은 소스**에서 얻는 게 핵심 — 타입은 컴파일하면 사라지므로, API 입력 검증은 런타임 스키마(zod)가 별도로 필요하다. 폴리글랏 경계(hub↔judge)는 언어가 달라 이 방식이 불가 → IDL(Protobuf/OpenAPI)로 계약. — 2026-07-25 12:48

### Prisma 마이그레이션 흐름
`schema.prisma`(선언) → `prisma migrate dev`(diff로 SQL 마이그레이션 생성+적용) → `prisma generate`(타입세이프 클라이언트 생성). 스키마가 코드의 단일 진실원이고 DB가 따라온다(선언적). seed는 별도 스크립트로 초기 데이터 주입. — 2026-07-25 12:48

## 프론트엔드 (arena / Next)

### next/font 셀프 호스팅 — CDN보다 나은 이유
`next/font`는 폰트 파일을 빌드에 포함해 자체 서빙한다: ① 외부 요청 0(프라이버시·안정성) ② `size-adjust` 자동 계산으로 **레이아웃 시프트(CLS) 0** ③ FOUC 방지. 구글 폰트도 빌드 타임에 다운로드해 셀프 호스팅으로 변환된다. — 2026-07-25 12:48

### 디자인 토큰 = CSS 변수 + Tailwind 매핑
색을 컴포넌트에 하드코딩하지 않고 CSS 변수(`:root`/`.dark`)에 단일 진실원으로 두고, Tailwind는 `rgb(var(--x) / <alpha-value>)`로 매핑만 한다. 값을 `"R G B"` 채널로 저장해야 `/60` 같은 투명도 유틸이 동작한다. 효과: 다크모드 전환 시 컴포넌트가 `dark:` 이중 표기 없이 변수 교체만으로 반응. — 2026-07-25 12:48

### RSC와 client island
서버 컴포넌트(RSC)가 기본이고, 인터랙션 덩어리(Monaco 에디터 등)만 `"use client"` 잎사귀로 격리한다. server-first를 교조적으로 밀면 안 되는 사례(Artsy 철회)를 반영 — 인터랙션 중심 화면은 client island가 정답. — 2026-07-25 12:48

### LLM median UI — 왜 AI가 만든 UI는 다 똑같은가
LLM은 학습 데이터의 통계적 중앙값으로 수렴한다(라운드 박스·제네릭 블루·시스템 폰트). 스타일 자체는 프로 문법이지만 "의도의 부재"가 아마추어 티의 정체. 탈출은 토큰·서체 같은 구조 개선(필요조건)만으론 안 되고 **과감한 취향 결정(컨셉)** 이 있어야 한다 — 1차 보수적 개편이 체감 실패한 교훈. — 2026-07-25 12:48

## 인프라 · 도구

### pnpm의 빌드 스크립트 차단 (supply-chain 방어)
pnpm 10+은 의존성의 postinstall 스크립트를 기본 차단한다(악성 패키지의 설치 시 코드 실행 방어). 네이티브 빌드가 필요한 패키지(`unrs-resolver`, `@prisma/*`)는 `pnpm-workspace.yaml`/`package.json`의 허용 목록에 명시해야 한다. 미승인 시 `ERR_PNPM_IGNORED_BUILDS`. — 2026-07-25 12:48

### 폴리글랏 모노레포에 JS 도구를 루트에 얹지 않기
pnpm 워크스페이스를 폴리글랏 루트에 두면 Go/Python 서비스까지 JS 도구 개념에 종속된다. `platform/`(TS 그룹) 계층을 하나 두고 그 안에서만 워크스페이스를 돌리는 게 격리 해법. Turborepo `apps/packages` 컨벤션이 폴리글랏에 안 맞는 것과 같은 이유. — 2026-07-25 12:48
